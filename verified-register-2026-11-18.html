2026-11-18 verified request register

One row per requirement in the request — 74 items, each with its status, its blocking gate, the number that clears it and its official referent — plus the brief's own numbers re-derived and 10 suggestions staged for a path choice before any change is implemented.

Three registers cover this request, and they are not duplicates — read the distinction. the standing-request register (CR1, 81 items) records what was built per item with the live spot-check verdict beside it; the CS5 register (81 items) inventories the same items against the commit it was written on; this register (74 items) is the one whose status is re-derived: every row opens the artefact it cites at build time under a fail-closed contract, so a cited file that disappears — or a declared gap that appears — fails the build instead of leaving a stale sentence. It also carries the brief's own numeric claims re-derived against verbatim official reads (15 rows, section 2), the 10 staged suggestions in section 3, and the two surfaces the brief asked for that existed nowhere: the deficiency matrix and the vig-free decomposition. Where the registers disagree, the disagreement is the finding.

This is a register, not a changelog. Nothing here changes a published research number: the model, the frozen pin and the competition rules were left exactly as they were. Statuses are re-derived from the files named in the Evidence column every time the site builds — a cited artefact that disappears, or a 'not built' artefact that appears, fails the build.

How to read this table

One row per item of the 2026-11-18 request. Status is what the repository can prove today, not what the plan intends. Evidence names the artefact and re-opens it: row counts and fill rates in that column are computed at build time by pipeline/request_register_20261118.py. Blocking gate is the thing that fails, and clears when is the number or artefact that would close it. Where an item is about a page the league publishes, that page is linked; where the item is a process rule, the note says so.
