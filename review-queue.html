How a decision is made here

  1. Nothing is implemented on a suggestion alone. Every proposal sits in one of 4 registers written by different sessions. This page merges them; it does not approve any of them.
  2. Choose a path, not a proposal. Where a cluster offers Path A / B / C, the choice is recorded against the cluster. Path A is the conservative option that changes nothing in the frozen model; Path C is the full rebuild. The recommended path is shown, but the recommendation is not a decision.
  3. Gates do not move. A suggestion that touches a validation gate changes the code that computes the gate, never the threshold. Threshold changes require a new pre-registration.
  4. An answer is recorded before work starts. If a cluster is blocked on an open question, that question is on Questions & answers with the discovery step named.
  5. The record stays. Every row keeps the register, the original id and the page it was published on, so the merge can always be undone by reading the source register instead.
