Decision protocol — how to choose a path

Six steps, in order
  1. Name the decision the suggestion unblocks, and the question it depends on.
  2. Check the evidence class. Official observation, primary method, commercial data licence, or opinion. Only the first two are in the repository today.
  3. Price the cost in money, weeks and permanent maintenance — not just in build effort.
  4. State the failure mode. What breaks, and who would notice? A silent corruption is worse than a visible error.
  5. Choose the smallest reversible step that produces evidence, and archive the current published tables first.
  6. Record the decision, the owner and the review date in the decision log below.
Scoring rubric

Score each option 1-5 on each line and record the total with the decision. The rubric is a checklist, not a formula: a BLOCKING gap outranks any score.

  • Decision impact — does it unblock a question marked BLOCKING?
  • Evidence quality — official, primary, licensed, or inferred?
  • Reversibility — can it be undone in one commit?
  • Cost — money plus recurring time.
  • Failure mode — is the failure loud or silent?

Everything is reversible if the published tables are archived first

A data refresh or a rule change moves the numbers. Before any path is executed, copy the generated tables to a dated folder so the prior publication stays reviewable. The current tables are reproducible from the pinned commit and the pipeline, but only for the commit they were built from.

What a decision must include before implementation

  • The question it answers, by ID from the question register.
  • The evidence class of the data it depends on, and whether that data exists yet.
  • The metric that will show it worked, fixed before the change, not after.
  • The rollback: the commit or archived table that restores the prior publication.
  • The owner and review date recorded in the log above.
