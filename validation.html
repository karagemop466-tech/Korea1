Validation gates

A fail-closed framework for separating evidence from variance.

Evidence boundary. Official observations, model estimates and community-market research are separate. Unverified observations are blank in the public tables, not filled in. Reproducible estimates remain in the clearly labelled research annex and downloadable CSVs; they are not betting recommendations.

Luck cannot be deleted. False confidence can be reduced.

Statistical tests are conditional on their assumptions. A non-significant result is not proof of no skill; a significant result is not proof of causality. The gates therefore combine design, data quality, economic value and untouched replication rather than relying on a single p-value.

Research statistics · Gate configuration · Library bootstrap result

What was repaired

  • Individual bets are not treated as independent observations for significance; weekly returns are used.
  • The reality check aligns every strategy on the same calendar weeks, including zero-return no-bet weeks, and resamples all strategies together.
  • Holm replaces a dependence-sensitive FDR claim. BH code remains only as a tested mathematical utility.
  • Deflated Sharpe uses weekly observations and a documented lower bound of prior trials. It cannot certify skill while the full search history is unknown.
  • Every “validated” label requires all eight gates, including redundancy and official quote provenance.
  • Power is computed from each candidate's weekly variance; a fixed 100-bet threshold is not described as adequate power.

Prospective acceptance protocol

  1. Freeze code, rules and source versions; record a manifest hash.
  2. Log every eligible event, quote timestamp and no-bet decision.
  3. Do not tune on the evaluation window.
  4. Settle using official results and the actual bookmaker's terms.
  5. Run the full gate battery and publish failures.
  6. Repeat on a second untouched window before recognition.
