Recommended path

A suggested order; nothing is implemented until you choose

  1. First — DH-02 (price provenance) and DH-04 (data freshness). Every other number on the site is conditional on these two. Without executable prices, no ROI can be validated; without a fresh pin, the board is describing a season that has already moved on.
  2. Second — DH-01 (evidence display). A one-line policy change that decides whether the leaderboard can be read at all. It is reversible and costs nothing.
  3. Third — DH-05, DH-06 and DH-07 (availability). Now that the deficiency join runs on every capture, this is no longer blocked on data collection; it is blocked on the decision to price it. Do not add it to the model without the availability gate (DH-05 option B).
  4. Fourth — DH-03 (prospective proof). It is already running and already hash-chained. It needs weeks, not code.
  5. Last — DH-10 and DH-11 (reward and staking). These are yours alone: the repository cannot answer them, and no reward should be defined before DH-02 and DH-03 produce evidence.
  6. Never — DH-15 option B. Relaxing a gate to let a strategy through produces a winner, not evidence. The build keeps all eight gates fail-closed and asks you to confirm that.

How a decision gets recorded

  1. Choose an option for one or more DH- rows on this page.
  2. Record it in DECISIONS.md with the date and the DH- id.
  3. Only then is the change implemented, in a pull request that names the decision it carries out.
  4. Nothing in this repository implements a decision on your behalf. The pages below are options and evidence, not actions taken.
