Methodology

How the lines are built, how the bets are settled, and how the numbers are checked.

Pipeline

pipeline/fetch_data.py     pin upstream commit, download archive, hash every file -> data/sources.json
pipeline/build_datasets.py  chronological walk-forward features (no leakage), audits -> games_model.csv
pipeline/models.py          three model families, walk-forward -> originated_lines.csv
pipeline/backtest.py        settlement engine, cross-checked against nflverse outcomes
pipeline/strategies.py      the pre-declared strategy library
pipeline/stats_tools.py     bootstrap, FDR, deflated Sharpe, reality check
pipeline/validation.py      run the library, apply the eight gates -> strategy_*.csv
pipeline/correlations.py    measured dependence -> corr_*.csv
pipeline/render_site.py     this site
pipeline/verify_site.py     row-level source check + internal link check

Reproduce with make build (or run the eight scripts in order). Everything is deterministic: the upstream commit is pinned and every download is SHA-256 hashed.

Probability, price and push

A margin (or total) is modelled as normal around the model line with a continuity correction, so a spread that lands exactly on the number is priced as a push rather than a half-win:

P(push) = Φ((L+0.5−m)/σ) − Φ((L−0.5−m)/σ)
P(win)  = 1 − Φ((L+0.5−m)/σ)

fair American price = 100·(1−p)/p        for p < 0.5
                    = −100·p/(1−p)       for p > 0.5

The published "posted" moneyline applies a 4.5% two-way hold, so the numbers on the Originated lines page are a bettable pair rather than a vig-free pair.
